# PATANYX ad-list allowlist -- hosts that must never reach the shipped ad and
# tracker rules, whatever an upstream list says.
#
# This is the ad blocker's counterpart to scripts/blocklist-allow.txt, and the
# bar for an entry is DIFFERENT. The malicious blocklist stops navigation, so
# its allowlist protects reachability. These rules silently drop subresource
# REQUESTS, so an entry here protects the browser's own plumbing and this
# project's first-party infrastructure from ever being filtered by a bad
# upstream pull -- and, below the first-party block, a host a site cannot
# work without, reproduced before it is added. Nothing else. "This ad network
# is legitimate" is NOT a reason: legitimate ad networks are exactly what the
# feature blocks.
#
# EXACT MATCH ONLY, same parse as the blocklist allowlist: removing
# `example.com` does not remove `sub.example.com`.
#
# Format: one host per line. Blank lines and lines beginning with # ignored.
# Inline # comments carry the reason.

patanyx.com          # First-party. The front door, AreaGram, Travel, Recall.
patanyx.net          # First-party. The web home.
edgexene.io          # First-party. The dl/ channel and the relay live under
                     # this apex; a rule here would break updates and sync.

# ---- Google gates and Maps imagery, added 2026-09-14 ----
# Not ad hosts. consent.google.com is the interstitial Google sends you
# through BEFORE it will serve Maps, Search or anything else; blocking it
# does not block an ad, it makes Google return "an error has occurred" and
# the site unusable. Reproduced on 1.0.0: with this host refused, a load of
# google.com/maps stops at the consent screen; with consent stored, the same
# page works with every other rule here still in force.
consent.google.com   # Google's consent gate. Blocking it breaks all of Google.
consent.google.com.af
consent.google.com.ag
consent.google.com.ai
consent.google.com.ar
consent.google.com.au
consent.google.com.bd
consent.google.com.mm
consent.google.com.pk

# ---- Spotify playback gateway, added 2026-10-05 ----
# Dual use. guc-spclient.spotify.com is one of Spotify's regional client API
# front ends (spclient). The web player registers itself as a playback device
# through it (track-playback/v1/devices) before it will play a note, and a
# host rule cannot separate that from anything else Spotify sends through the
# same host. Upstream files it under Tracking. Reproduced on Windows 1.0.x:
# with this host refused, the web player signs in and can remote-control a
# phone, but cannot play in the browser; with ad and tracker blocking off, the
# same page plays.
guc-spclient.spotify.com  # Spotify device registration and playback.
# NOT allowed, deliberately: pixel.spotify.com, pixels.spotify.com,
# adeventtracker.spotify.com, crashdump.spotify.com, bloodhound.spotify.com
# and ads.spotify.com. They are ads and telemetry, not the player.

# ---- Dailymotion video delivery, added 2026-10-10 ----
# dmxleo is Dailymotion's video CDN: every video page fetches its stream
# manifest from dmxleo.dailymotion.com/cdn/manifest/video/<id>.m3u8 and the
# segments follow. ShadowWhisperer lists it as an ad host; blocking it is
# "Playback error" on every Dailymotion video. Reproduced in a PATANYX 1.0.6
# development build on WebKitGTK 2.54 (Linux; WebView2 not reproduced; engine log: "content blocker prevented ... loading a
# resource from https://dmxleo.dailymotion.com/cdn/manifest/video/...").
# The ad servers the player calls stay in the shipped lists; dmads.dailymotion.com,
# the ad library, is allowed below.
dmxleo.dailymotion.com
dmxleo.com           # The same CDN's own apex, from the Tracking list.
# dmads.dailymotion.com is Dailymotion's ad LIBRARY, not an ad server, and the
# player will not start without it: with this one host blocked every video
# shows "Playback error". With it allowed, loads where no ad is scheduled play
# normally and the ad servers it calls (pubads.g.doubleclick.net and others)
# stay blocked, so no ad plays; loads where an ad IS scheduled still end in
# "Playback error" (open, ads-notes/P0-RESULTS.md item 3). Bisected host by
# host in a PATANYX 1.0.6 development build on WebKitGTK 2.54 (Linux),
# 2026-10-10; WebView2 not reproduced.
# Absent from the upstream lists today; this entry keeps it that way.
dmads.dailymotion.com

# ---- Instagram's own API, added 2026-10-10 ----
# gateway.instagram.com, graphql.instagram.com and graph-fallback.instagram.com
# are instagram.com's own API endpoints (its page scripts call them for the
# site's own content); the upstream Tracking list carried all three, found in
# a sweep of Meta hosts on 2026-10-10. NOT yet reproduced in a signed-in
# session (no Instagram account on the test server); on the Windows checklist.
# Allowed now on the same rule as the Dailymotion CDN above: a request filter
# must never cut a site off from its own API. Instagram's ad and telemetry
# hosts stay listed.
gateway.instagram.com
graphql.instagram.com
graph-fallback.instagram.com
